# AGENTS

## Vision

Magix Cache is a library designed to optimize caching during PHP SSR (Server-Side Rendering).
By specifying Magix Cache during data retrieval, you can easily achieve optimized caching, specifically for read model caches and page caches such as CDN and browser caching.

Magix Cache separates cache metadata bubbling from explicit overrides. Composition derives inherited metadata from dependencies; a boundary deliberately overrides the fields it configures.
For example, in a FooBarQuery that retrieves both Foo and Bar, if Foo has a 20s cache and Bar has a 60s cache, FooBarQuery inherits 20s when it only composes these caches. An explicit parent TTL of 60s overrides that inherited lifetime.
It also optimizes other cache-related elements, such as the cache sharing scope and the presence or absence of a cache.

The fundamental concept is to provide an easy interface for users while offering a simple and highly extensible mechanism at its core.

## Architecture

This repository is a Composer monorepo with a framework-independent core and separate integration packages.

### Boundaries

- `packages/magix-cache` contains the framework-independent core and depends on PSR contracts and Guzzle Promises through its own `Async\Promise` adapter.
- `packages/magix-cache-laravel` and `packages/magix-cache-symfony` are framework adapters that connect each framework's cache service to Magix Cache.
- `packages/magix-cache-cli` is a development tool that reads a project statically and reports its cache boundaries; it depends on the core but nothing depends on it.
- The root `Magix\Cache` namespace is reserved for `Cacheable`, `Cached`, `AsyncCached`, `CachePolicy`, and `CacheRuntime`.
- `Metadata` owns the immutable metadata value type, its dependency meet law, and explicit field replacements and depends on nothing else. `Attribute` declares policies and behaviors, `Composition` combines cached values, `Strategy` owns the composable strategy contract (`CacheStrategy`, `CompositeCacheStrategy`, operation-specific read/write values, and the `Contract` attributes), `Runtime` owns declaration resolution, execution stages, the runtime registry, and extension contracts, `Observation` owns the observer and event contracts shared by Runtime and individual strategies, and `Cache` owns storage contracts and PSR adapters.
- Use `CacheKeyStrategy` for key formats, the extension contracts in `Runtime\Extension` (`CacheTtlResolver`, `BackendErrorClassifier`) for purpose-specific behavior, `Observation\CacheObserver` for diagnostics, and the `Cache` port or a decorator for storage topology. Strategies are middleware over cache operations. Their composition is ordinary function nesting; fetch middleware can transform a returned Cached within the boundary's value type and handle exceptions from its delegate. The cached callback takes no arguments; there is no origin request or argument-rewriting API. The runtime decides when to invoke the composed fetch, and the runtime inquiry invokes the origin closure.

### Execution flow

```text
query -> Cacheable::cached(fn) -> attribute declaration resolution -> CacheInvocation
      -> CacheRuntimeRegistry -> CacheRuntime fixed stages
         (lookup -> fresh-hit judgement -> optionally wrapped fetch() -> re-judged store)
      -> GuardedCache -> Cache -> PSR adapter
```

`cached()` and `asyncCached()` each take exactly one closure and is the anti-corruption layer between PHP and the internal model: it captures the call site, resolves the static declaration, and delegates. Policy, behaviors, and the runtime reference come from attributes alone — `#[Cache]` on the method wins over the concrete class as a whole, behaviors (`#[StaleIfError]`, `#[DynamicTtl]`, `#[BypassCacheErrors]`, `#[UseStrategy]`) follow the same precedence and are disabled with `enabled: false`, and parent-class attributes are never inherited implicitly. There is no per-call override path.

`#[UseStrategy]` names a class whose public static `create()` returns a `StrategyDefinition`: typed configuration in, immutable construction recipe out. With static factory arguments, only this recipe is memoized. `#[StrategyArgument('name')]` on a boundary parameter binds its current value to the active factory: in that case only the binding plan is memoized, and `create()` produces a new recipe for every invocation, including hits. A destination must be a declared non-variadic value parameter and has exactly one source; static named/positional arguments and parameter bindings cannot overlap. `StrategyDefinition::of()` describes a constructible `CacheStrategy` and its arguments; `CompositeCacheStrategy::compose()` composes definitions, and a composition composes again. The runtime constructs every executable strategy and nested child afresh for each `cached()` invocation, including nested calls and fresh hits. One execution uses the same objects across `get/fetch/set`. A strategy owns its own execution state; it is not required to be pure or reusable across invocations. Definition arguments allow values, enum cases, arrays and nested definitions, never executable objects or closures.

`CacheStrategy` is middleware only: `get(string $key, Closure $next): ?CacheRead`, `fetch(string $key, Closure $next): Promise`, and `set(string $key, CacheWrite $request, Closure $next): void`. Each continuation performs exactly that operation: get takes a key, fetch takes no arguments and returns `Promise<Cached<mixed>>`, and set takes a key plus write request. Fetch's key identifies the boundary for key-dependent metadata rules; it is not an origin input. Get/set can rewrite their arguments; every middleware can transform its result or handle declared failures from its own delegate. `ComposedCacheStrategy` owns ordinary closure nesting and implements this same interface. Empty compositions are identities. With no declared Strategy, Runtime invokes its actual operations directly. `CacheExecution` performs those operations and does not implement `CacheStrategy`; there is no Next strategy, sentinel, terminal Strategy or shared operation context.

Clocks and observation are constructor dependencies, separate from operation data. `StrategyFactory` supplies missing constructor parameters typed `ClockInterface` and `CacheObserver` from the active runtime. `StrategyDefinition::instantiate()` accepts this construction closure and forwards it to nested definitions; the memoized definition never retains the closure or service instances. Individual strategies notify their injected observer directly; Runtime does not interpret strategy diagnostic strings. Ordinary runtime hit/miss and backend observations remain available.

`get()` exposes retained data through `CacheRead`, and Runtime judges freshness after middleware returns. On a miss, it invokes the optional fetch middleware around the argument-free origin inquiry and local policy, parameter and dynamic settings. A middleware can return without delegating; there is no separate origin call in that case. Every resolved Cached enters the same set operation, registered by Runtime in `Promise::then`. `CacheWrite` carries only the Cached and requested retention. `StaleIfErrorCacheStrategy` alone owns its candidate, exception selection, age judgement, StaleServed notification, suppression of a write of its selected candidate, and retention policy. It implements these through get/fetch/set middleware. `#[StaleIfError]` is normalized into this same strategy behind the user composition. The common Strategy contract has no stale or origin-source protocol.

The runtime inquiry uses one origin-success base time for policy, parameter and dynamic TTL. Each middleware chooses the time for its own relative expiration; KeySpreadExpirationStrategy reads the clock after its delegate returns. Metadata priority, from lowest to highest, is: bubbled origin metadata, explicit policy fields, parameter settings, dynamic TTL, then Strategy overrides. Strategies act on the fetch return path: in `compose(A, B)`, B returns first and A overrides last. This is ordered override, not metadata bubbling. `Cached::of($result->value(), $result->metadata->withExpiration((float) $this->clock->now()->format('U.u') + $ttl))` replaces only expiration. The same construction with `CacheMetadata::withTags/withVisibility/withCacheability/withReasons` makes field-specific changes. A value-only override can use `Cached::map()`. A middleware that needs one time across its own work captures it locally; the common fetch contract carries no shared origin timestamp. Strategy contracts on `fetch()` describe its own overrides; no TTL/ExpiresAt contract on a readable strategy means expiration is preserved, and no `#[WritesMetadata]` means visibility, tags and cacheability are preserved. `#[WritesMetadata]` without arguments declares that all three are replaced with values the declaration cannot describe; naming fields declares exactly those. As with every contract here the implementation is free as long as it honors what it declared: writing a field it did not name breaks its own contract. A composition never re-declares child contracts. `#[AssumeTtl]` is analysis-only and covers exactly its named child.

`#[CacheTtl]`, `#[CacheTags]`, and `#[CacheVisibility]` supply explicit invocation overrides. The last annotated parameter in declaration order wins for each field; there is no minimum or union between these settings. Parameter visibility and tags replace static policy fields before lookup; a resolved NoStore skips reads. CacheScope supplies a static parameter visibility, with the last scope winning before invocation bindings. All parameter values are validated even when a later parameter wins. Bound parameters cannot be ignored or variadic. A key reducer may reduce the source value, but the evaluated overrides and immutable strategy recipe also enter the key under `@configuration`. The declaration fingerprint includes the user's binding destinations and omitted versus explicit fields.

All method arguments form the key by default, together with the runtime namespace, the concrete class, the declaring method, the policy version, and a fingerprint of the effective declaration; use `#[CacheKey]` for stable reduction and `#[CacheIgnore]` only for values that cannot affect output.

Key declarations and invalidation versions belong to the user. Do not add library release numbers, internal semantics versions, or automatic key changes for backward compatibility. Implement the current contract directly, without compatibility shims or legacy fallback paths.

Runtimes are registered by name in `CacheRuntimeRegistry` at bootstrap and never rebound; an unknown reference is a definition error, not a fallback. `CacheRuntime` executes a `CacheInvocation` through a stage order that never depends on attribute order. Each middleware catch covers its delegated fetch call, including any inner middleware and actual inquiry work. Only cache reads and writes are inside the backend bypass range. The runtime owns conversion between public `Cached<T>` and internal `CacheEntry<T>`; these types must remain independent. `expiresAt` controls freshness, `retainedUntil` controls physical retention for stale handling, and extending retention never changes the expiration.


`AsyncCached<T>` owns a private `Async\Promise<Cached<T>>` and never returns that promise. `Promise::fromGuzzle()` imports a transport, `then()` adopts returned promises, and `recover()` handles only declared RuntimeException failures. `cached()` waits for the common promise pipeline; `asyncCached()` returns its AsyncCached immediately. Both accept a closure returning Cached or AsyncCached. Origin work is scheduled through the Guzzle queue, and Runtime attaches storage after fulfillment. No failed fetch writes. The origin-completion time is the common local TTL base time, and storage is re-judged at actual write time.

Async map/flatMap/flatten/zip/unzip/sequence/traverse/combine2..combine10 do not wait. `toCached()` and `value()` are explicit synchronization boundaries. Async flatMap adopts another AsyncCached; flatten removes one AsyncCached layer. `AsyncCached<Cached<T>>` is a valid payload: conversion gives `Cached<Cached<T>>`, then Cached::flatten meets the two layers. fromCached lifts a complete result; of and fromPromise preserve nested Cached payloads. Metadata laws, key configuration and override precedence remain the same. The CLI follows both boundary methods and both composition APIs without executing promises.

### Bubbling and overrides

`Cached<T>` carries an evaluated value and immutable `CacheMetadata`. Dependency bubbling uses `CacheMetadata::meet()`, a fixed law with `top()` as its identity. This law applies to composition, not to explicit overrides:

- use the earliest finite expiration (`null` means unconstrained, never "unknown");
- combine cacheability with AND;
- choose the stricter visibility: `Shared < Private < NoStore`;
- union tags and diagnostic reasons.

`map()` keeps this value's metadata. `flatMap()`, `flatten()`, `zip()`, `sequence()`, `traverse()`, and `combine2()`..`combine10()` meet the metadata of every input. `flatten()` removes exactly one `Cached` layer. `unzip()` puts the whole pair's metadata on both projections. `sequence()` and `traverse()` consume iterables eagerly, preserve keys, and meet even overwritten items; empty input has `top()` metadata. `Cached` has no magic forwarding or `@mixin`: property access, method calls, array functions, iteration, and string conversion use the explicit value or a composition callback. Extracting a value with `value()` detaches it from its constraints, so a dependency obtained inside `map()` must be chained with `flatMap()` or `combineN` instead.

Policy application is pure (`PolicySemantics`) at the origin base time. A fixed TTL replaces expiration, including a shorter or expired dependency deadline. `Ttl::Auto` is the absence of a declared lifetime — `#[Cache(ttl: Ttl::Auto)]` is exactly `#[Cache]` — so it preserves expiration and validates nothing; higher-priority parameter, dynamic and Strategy overrides can still replace it afterward. A boundary whose composition supplies no finite expiration is not a defect: it simply stores nothing, which the existing storability judgement already decides, and the CLI reports as proven `no` rather than a runtime choice. Omitted policy tags and visibility are `null` and inherit; explicit `tags: []` clears tags, explicit Shared replaces Private or NoStore. Cacheability and reasons inherit unless a Strategy declares it replaces them with `#[WritesMetadata]`. A TTL-only override never changes the other fields. StaleIfError returns its selected Cached with the stored metadata. Outer middleware receives that ordinary result and can override it; StaleIfError suppresses the write and emits StaleServed only if the selected object itself reaches its set(). To preserve expired metadata through a TTL composition, place StaleIfError outside its TTL writers. An automatic parent preserves an expired dependency deadline, while a parent that explicitly overrides TTL can cache the composed result anew. Store only cacheable results with permitted final visibility and a future finite expiration, re-judged immediately before writing.

Cache reuse preserves complete evaluated metadata, including fractional absolute expiration, tags and reasons; hits never restart lifetimes or reapply overrides. For unchanged source results, declarations, evaluated overrides and base times, replacing any subtree with its stored result must leave all ancestor metadata equal. Protect this with the retained-subtree matrix in `tests/Integration/MetadataBubblingTest.php` across memory and serialized PSR adapters. At a new base time, a recomputed parent's explicit relative TTL can extend beyond a retained child's expiration. An automatic parent still inherits the child's absolute deadline. Equality with a different source generation or different Strategy decisions is not promised.

### Failure contract

Failures are split by who has to act on them, and the split is enforced by php-ai-toolkit's rules plus PHPStan's checked-exception analysis.

- `RuntimeException` and its subclasses are declared behavior: the caller is expected to handle them. `Cache\CacheBackendFailure` is what the `Cache` port declares, and `Cli\Key\CacheKeyUnresolvable` is what the key command reports. The bundled adapters translate a backend's own failures into these types and pass the original as `previous`.
- `LogicException`, `InvalidArgumentException`, and `Error` raised *by this library* mean this library or its caller is wrong. They are never expected in a test and never part of a declared behavior. Fix the origin instead.
- Every direct `throw` carries a `@throws` tag naming a concrete type, and a catch names the type it can actually handle.

The two failure-handling behaviors follow the same split instead of escaping it. `StaleIfErrorCacheStrategy::fetch()` handles exactly `RuntimeException` through `Promise::call($next)->recover(...)` and chooses an eligible retained candidate only for its configured exception types. If it cannot answer, it rethrows the same exception. The catch covers the delegated inquiry, including inner middleware and the origin and local boundary settings; it never covers get or set, or an outer middleware. A bug (`LogicException` family, `Error`) never enters this catch. Other middleware can use Promise rejection continuations to return a freshly computed replacement or retry a delegated inquiry. Synchronous try/catch alone cannot handle a later rejection. Neither the common Strategy contract nor the runtime distinguishes these returned values. An origin that meets an expected outage in a foreign hierarchy — a PSR-18 client, `Doctrine\DBAL\Exception`, `JsonException` — translates it into its own declared `RuntimeException` subtype when it wants this recovery behavior. Likewise `GuardedCache` catches exactly `RuntimeException` around cache reads and writes, because `CacheBackendFailure` is what the `Cache` port declares; the `#[BypassCacheErrors]` classifier decides within that family, and failures outside it propagate as port contract bugs. There is no broad catch or failure wrapper in the common fetch path.

Everywhere else the catch names what it can actually handle, and "the caller's code might throw anything" is not a reason to widen it:

- `HashCacheKeyStrategy` catches `Exception`, which is how PHP reports a value `serialize()` refuses. An `Error` from the caller's own `__serialize()` is a bug in that method and escapes, because relabelling it as an unusable key would hide it.
- `KeyCommand` catches only `CacheKeyUnresolvable`. A reducer that throws is not its business: the console application is already the boundary that renders a failure, and it reports the file and line, which an `$io->error()` on the message alone would have thrown away.

When a toolkit rule and the specification disagree, the specification wins and the exemption is written down. But "the rule is wrong here" has to be argued from what the code must do, not from how many errors it removes.

A precondition is checked where the value enters. `CachePolicy` and `#[Cache]` take a plain `int` for a lifetime, because that is what an attribute argument can be, so both check that it is zero or greater; the same holds for the version, the tags, and a dynamically resolved TTL. Declaring `int<0, max>` in PHPDoc instead is not a substitute: it binds only a caller who runs PHPStan over their own code, and this is a library. Write the check, declare it with `@throws`, and do not write a test that asserts a rejected value is rejected.

Check it once, at the boundary, and let the types carry it from there: `CacheTokenSet` turns `list<string>` into `list<non-empty-string>`, and `CachePolicy` runs it at construction so an unusable tag fails when the policy is written rather than when the boundary first executes.

### Static analysis

`packages/magix-cache-cli` reproduces these rules without executing code. `Reader` turns syntax into declarations, `Graph` applies the composition invariants and records analysis problems, and `Render` formats the result. The CLI exposes `analyze` and `key`; there is no separate inventory or lint command. Any change to policy resolution, key derivation, or composition must be mirrored in `EffectCalculator` and represented in the affected analysis node's problems when the declaration cannot hold.

The CLI works in a different value domain from the runtime: the runtime evaluates absolute times and real values, while the CLI propagates declared bounds and conditions as an abstract TTL estimate that keeps "known", "unconstrained", "unknown", and "invalid" apart. An unknown estimate may still carry proven bounds — `30-60s`, `30-?s` (undetermined, not unlimited), `≤60s` — and a statically unknown expiration is never converted to `CacheMetadata::top()` or to a concrete number — an unknown dependency under a `#[Cache(ttl: 30)]` parent is "at most 30s", not "30s".

The CLI reads parameter configuration without execution. Supplied arguments remain unknown even when defaults exist. Parameter and dynamic TTL overrides supply finite expirations but replace earlier numeric bounds; a known Strategy override may then replace them. Parameter tags and visibility replace earlier metadata with explicit uncertainty. An explicit parent field removes inherited uncertainty for that field. ParameterEffects checks source declarations, and StrategyResolver checks factory destinations; their problems are displayed by analyze.

`analyze` follows returned metadata through ordinary methods and cached origin closures. `value()` extraction and plain returns contribute no metadata; returning a `Cached` intact preserves it. `map()` keeps only the receiver metadata, while explicit composition meets its inputs. `if`/`elseif`, ternaries, `switch` (including fallthrough), and `match` keep exclusive paths as alternatives. Composition takes the product of independent alternatives, retaining the TTL, visibility, and tags of each possible result; aliases of one selected value remain correlated. `EffectCalculator` applies each boundary's policy and invocation settings separately to every alternative. Tree and Mermaid show compact effective summaries; JSON exposes full `metadataAlternatives`. Display filters never alter these candidates. Opaque transformations, unsupported control flow, recursion, and bounded path expansion remain unknown. Record source causes and affected fields only where returned metadata cannot be followed; the mere absence of `#[Cache]` is not an analysis gap. Display depth never limits analysis.

`analyze --uncached=between|all|none` selects rows after analysis using the effective `#[Cache]` attribute alone (method or applicable concrete class), independently of return types, observed `cached()` execution, errors and diagnostics. `all` includes every analyzed method. Default `between` retains declarations and unattributed methods with both an attributed ancestor and an attributed descendant in the unignored hierarchy. `none` retains declarations and promotes visible descendants. The analyzed method itself is exempt from row selection: it names what the report answers, so an entry point that converts its result and declares no cache still heads its own report, and only `--ignore` removes it. An unattributed row under a cache declaration is exempt for the same reason whenever it provably returns something other than what it composes: omitting it promotes its callees under that declaration, which would attribute the caller's metadata to dependencies the row detached with `value()` or kept only part of. Only a determined return makes that claim; a return the analyzer could not follow stays promotable, because the caller's own row already carries the uncertainty. A row that reports what it composes folds its callees in either way, so nothing is exempt below an unattributed caller. A compact mode may therefore leave out a method, never explain a result by something that did not produce it. `--ignore` prunes the matched node and its entire subtree before promotion. Depth counts printed rows, not original calls, so an omitted method never spends the budget a displayed one needs and a compact mode never reaches less far than `all`. Every projection retains the original metadata, alternatives and field certainty.

A method that stores nothing also reports what it composes: the meet of the cache boundaries it reaches, folded through ordinary callers, with a cache boundary answering for its own subtree. This page-level estimate answers what a response built from the method is bounded by, so it survives a `value()` extraction that detaches metadata for the caller and an unverified propagation gap. It is never storage proof, never a policy, and never replaces the returned metadata beside it: `composes ttl 20s  private  tags a,b` on a controller action says its data came from those caches, not that the action caches anything. It is computed from the whole analysis, so display filters never change it, and it is absent for a cache boundary and for a method that reaches none. JSON reports it as `composed` next to `effective`, without `storable` or `storage`.

The analyzer owns detailed declarations, call resolution, returned metadata, local diagnostic causes and affected-field references. JSON exports selected nodes in a consistent `roots`/`diagnostics` envelope, including independent `declared`, `execution`, return type and parameter facts; cause definitions are deduplicated and affected fields refer to their IDs. Tree and Mermaid are compact overviews: one row per method, no separate header, expanded alternative lists or diagnostic prose. A hidden unrelated cause must not affect a parent's certainty, storage label or color. A hidden cause affecting returned metadata remains referenced by the relevant fields without reprinting its message on an ancestor. Explicit field replacement clears inherited uncertainty only for that field; local cause information remains available in the detailed model.

Partial analysis is a usable result, not a declaration defect. Retain known structures and fields. Tree values can use `?` or grounded references such as `10s?`, `shared?` and `tags product?`. References stay separate from the abstract TTL and metadata domains and must never become numbers, bounds, finite-expiration proof, guaranteed visibility/tags or storage proof. Conflicting references render as `?`; metadata reference candidates and their sources remain in JSON. Proven facts take precedence: `≥private` is a proven Private floor, while `private?` is only a reference. `tags product,?` guarantees product with an unknown remainder; `tags product?` does not guarantee product. Plain payloads and `value()` extraction do not supply metadata references. Explicit policy fields, runtime parameters and readable Strategy writers discard replaced references; opaque Strategy writers can retain references from before their replacement stage. JSON keeps `ttlReference`, `visibilityReference` and `tagsReference` independently of effective constraints. A known finite runtime duration renders as `dynamic`, separately from incomplete analysis. Attribute-only migration methods remain visible as `[declared]`, while their effective returned metadata never applies a policy whose `cached()` execution was not observed. Confirmed declaration problems remain data with a compact marker; execution failures remain errors.

`#[Ttl(30, new TtlRange(min: 600, max: 900))]` declares alternative finite constraints and renders as `30/600-900s`. `#[Ttl(30)]` declares exactly 30 seconds, while `#[Ttl(min: 600, max: 900)]` declares a range. Positional alternatives and named bounds cannot be mixed; use `TtlRange` inside an alternatives list. The `oneOf` and `unconstrained` options are removed. An omitted or empty `#[Ttl]` on a readable strategy means it does not override TTL; an unreadable class or factory stays unknown. `#[AssumeTtl]` supports the same lifetime syntax after its named child; supplying only the child explicitly assumes no added constraint. The CLI retains a normalized union of intervals, uses pairwise minimum images for dependency bubbling, and uses replacement for fixed policies and ordered Strategy overrides. Detailed gap paths remain available in JSON; inherited cause references survive only in fields still depending on them. It never takes a convex envelope unless uncertainty actually fills those gaps, never substitutes set intersection for lifetime composition, and never assumes correlations between the predicates selecting different strategies' alternatives. The proof of a finite expiration propagates independently of whether its numeric TTL is known, including to automatic parent policies, until an unknown override replaces that proof. Invalid alternatives and missing references are reported as strategy problems by `analyze`.

`#[ExpiresAt('12:00', until: '12:15', timezone: 'Asia/Tokyo')]` on `fetch()` declares a finite daily wall-clock candidate independently of TTL seconds. Omit `until` for a point; an earlier end crosses the local date boundary. Repeat the attribute on one `fetch()` for multiple times/windows; source and reflected readers retain every declaration and validate/bind each independently. Constructor references bind actual construction values, including unknown invocation parameters. The strategy owns occurrence selection, distribution, rollover, and DST behavior. CLI analysis preserves clock fields through nested strategies, inheriting dependencies, and all renderers; it never invents seconds from its own clock or assumes a day is 86400 seconds. Multiple clock contracts on one fetch describe simultaneous promises about its selected expiration, not intersected local windows. Different strategies override in return order. JSON strategy steps retain each candidate and the overview shows `expires by` for the surviving daily deadline. A fixed TTL or higher-priority expiration override removes the previous daily deadlines from the effective result, while per-step candidates remain visible. A valid clock contract proves finite expiration, so an automatic parent that inherits it stays provably storable. Missing references and malformed declarations are strategy problems. An omitted TTL adds no relative duration constraint but must not hide an explicit `ExpiresAt` contract.

For strategies the CLI analyzes the same declarations the runtime executes: `StrategyReader` reads a strategy class into its constructor and `create()` parameters, its composed construction definitions, and its contract attributes; `StrategyResolver` binds the `#[UseStrategy]` arguments, follows `StrategyDefinition::of()` and composed definitions, resolves each `ConstructorArg`/`Arg` reference against the bound construction (a reference to a missing parameter is a declaration error, reported in the analysis node's strategy problems), and applies the child contracts in fetch return order, with the outermost explicit override winning. Each child candidate stays visible, but only the winning override determines effective expiration. An opaque outer strategy erases earlier bounds; a known outer override can replace an opaque inner estimate. Declaration errors remain errors even when their metadata would be overridden. The bundled strategies outside the scanned sources are read through their reflected contract attributes without executing user code; a `create()` body the analysis cannot follow stays unknown unless an explicit `#[AssumeTtl]` covers that one child.

Keep PSR/backend details in adapters, preserve dependency bubbling and the separate override priority, and add tests beside the owning package. Before completing a change, run `composer config:validate`, `composer packages:validate`, `composer security:audit`, `composer lint`, and `composer test`. `composer lint` runs php-cs-fixer, PHPStan with the php-ai-toolkit rules, LocGuard, TreeGuard, and Deptrac; run `composer toolkit:install` once per checkout to get the toolkit's setup skills.

`composer doc-gen` renders the contract itself: every `@throws`, the types on both sides of a boundary, the deptrac layers, and — after `composer test:coverage` — the test cases that cover each method. It is a generator, not a gate, so it stays out of `composer lint`. Read it when changing a declared failure or a public signature: if the page does not say what the change means for a caller, the PHPDoc does not either.


TTL/ExpiresAt contracts describe expiration only. Readable strategies preserve other fields unless `#[WritesMetadata]` declares their replacement; those replacement values remain runtime-dependent. Unreadable strategies retain analysis uncertainty. `#[AssumeTtl]` covers expiration alone, and later parent settings can explicitly replace affected fields.

CLI presentation colors describe behavior rather than storage proof: normal declared rows (including runtime TTL/visibility and custom Strategies) are white; unattributed methods, NoStore, effective TTL 0 and a proven absence of any expiration are gray. Explicit bubbling override fields are yellow. Invalid TTL and confirmed declaration problems have compact red markers, without turning diagnostic descendants into colored ancestors. Tree and Mermaid preserve the same compact values; JSON retains conservative storage proof, per-field certainty and independent source causes.
