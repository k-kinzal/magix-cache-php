Deriver afc9851 caller-pruning evaluation

Evaluated on 2026-10-19 against upstream main afc98516f758f78c6c43d96e084c040d684b3fb3 (rechecked before publishing). The package is k-kinzal/deriver; its CLI is named deliver.

Decision

Caller pruning is useful and the previously reported exception-region gaps are fixed in these probes. Latest Deriver cannot currently be installed into Magix under the packages' declared dependency constraints. An isolated API migration preserves all characterized outputs, but is slower than the existing integration. Do not treat this as a completed production dependency update.

The production lock remains on e59f993. The new public API was exercised using an unmodified, separate installation of afc9851. A migration patch is retained as an experiment, rather than merging code that cannot be installed normally. The PR is draft pending an installable migration and its required validation.

Changes reviewed

The upstream comparison contains candidate-contract fixes and two substantial refactors. The previous Analyzer, ProjectInput, SourceFile, entry-point binding and assessment API has been replaced by Deriver::prepare($paths, $config) and derive($selector). Results are CandidateCollection values containing analyzed native values or partial terms, evidence, statistics and an interrupted flag.

The query contract explicitly describes source candidates. Default discovery keeps both arms of false ? 30 : 60; BranchEvaluators::truth() requests predicate evaluation and pruning. Loop recurrences remain dependencies rather than being executed to obtain their final iteration value. Neither behavior is treated as a regression against execution semantics. The relevant questions are whether source values are retained, dynamic dependencies are visible, and the consumer can select the intended invocation contexts without inventing argument combinations.

The evaluator API supports lazy application-defined evaluation. Caller-path selection restricts caller discovery before actual arguments are derived. forCaller() instead filters already-derived evidence and retains unconstrained candidates; it is not proof that a matching invocation exists.

Installation blocker and evaluation environments

Running composer update k-kinzal/deriver in the worktree fails with:

k-kinzal/deriver dev-main requires symfony/console ^6.4
but it conflicts with your root composer.json require (^7.4 || ^8.0).

--with-all-dependencies cannot make disjoint root requirements compatible. Both the root and the Magix CLI package require the newer Console range. Latest Deriver also requires YAML ^6.4; Console is the demonstrated hard conflict. No dependency metadata was edited or aliased to hide the conflict.

Two environments were deliberately kept distinct:

  1. Official standalone installation: Deriver afc9851, Console/YAML 6.4.48, PHP-Parser 5.9.0. All candidate and pruning probes use this installation.
  2. API-only Magix experiment: the existing Magix vendor installation and Console 7.4.18, with only the Deriver\\ autoload prefix redirected to the unmodified latest source, plus the migration patch. This bypasses dependency resolution for an experiment. Its successful tests do not establish a supported Composer installation or the upstream suite's Console compatibility.

Trying the migration with the standalone Console 6.4 instead causes all 33 frozen report cases to error: Magix's Application::addCommand() does not exist in that Console version. Downgrading Magix is therefore not a lockfile-only fix. Upstream should test and allow current Console versions, or separate the library's dependency surface from the CLI. This is the highest-priority feedback.

The host is PHP 8.5.8. Deriver uses PHP 8.3 target semantics; PHP-Parser stays at 5.9.0. No internal Deriver budgets were increased.

Candidate behavior and previous feedback

The prior C1 continuation-loss and C2 throw inconsistencies no longer reproduce:

  • try { $ttl = 30; } finally {} return $ttl; retains 30.
  • The analogous try/catch retains structural candidates 30 and 60. The catch candidate is acceptable under the source-candidate contract.
  • A throw-only function produces a NoValue partial with NO_VALUE_DEFINITION, not an analyzed null.
  • Explicit throw statements, throw expressions and arithmetic exceptions in the tested catch regions all retain the catch return 60.

Unknown parameters, supplied inputs with defaults, request data and environment reads retain EXTERNAL_INPUT dependencies. A partial array keeps its known head and tail. One branch selecting two fields yields [30, "a"] or [60, "b"]; subtracting a selected value from its alias yields zero. Unknown conditions are not pruned just because another condition candidate is known.

A finite summation loop now retains LOOP_DEPENDENCY, consistent with the documented structural contract. The truth evaluator selects zero-iteration and one-iteration examples correctly. The two-iteration and 10,000-iteration fixed-assignment examples both retain 11 and 27 and construct the same number of nodes. This is bounded candidate discovery, not final-value execution. A recursive countdown retains an enumeration partial by default and produces 8 with truth evaluation. These probes do not prove complete handling of all PHP constructs, recursive call graphs or real applications.

Magix migration experiment and equivalence

The migration patch adapts only ExpressionDeriver and the Term import in its test. The experiment:

  • registers BranchEvaluators::truth() so generated alias-budget conditions preserve Magix's characterized scope and expansion limit;
  • supplies captured inputs through lazy evaluators and a generated caller;
  • selects __magix_entry -> resolve#return;
  • accepts only one analyzed candidate with no collection interruption;
  • preserves native null separately from the unresolved sentinel.

The public preparation API currently accepts local files. The old in-memory source and explicit entry-input facilities are gone, so the prototype writes and removes a temporary source file per generated snapshot. It does not execute application code. This is a correctness experiment, not a production-hardened filesystem adapter: its failure contract, PHPDoc, lint and documentation still need review before promotion. It is not present in the active source tree.

With the API-only overlay:

  • All 33 frozen JSON/Tree/Mermaid reports match without regenerating them.
  • The 61 literal cases and alias identity/scope/cycle/budget checks pass.
  • 3,072 numeric combinations match the original 688356c3 reader.
  • All 3,497 tests / 22,874 assertions pass (sequential PHPUnit).
  • Full Analyze JSON for 8,192 tags and the valid 8,192-entry negative-key Strategy map matches the original reader, including all entries.

No new output regression was found in this characterized replacement domain. This claim does not extend to replacing Magix's metadata/control-flow analysis or using arbitrary application bodies as concrete singleton expressions.
